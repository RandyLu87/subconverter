# PRD:出站模式切换(规则 / 全局 / 直连)

> 编号:10 · 状态:待评审 · 关联:[07-prd-policy-groups.md](07-prd-policy-groups.md)、[08-prd-clash-to-singbox.md](08-prd-clash-to-singbox.md)
> 落地方案见 [11-plan-outbound-mode.md](11-plan-outbound-mode.md)

## 1. 背景

Nest 目前所有流量只有一种路由行为:按配置里的规则链分流(即 Clash 生态的「规则模式」)。用户无法临时切换到:

- **全局模式**:所有流量走代理(排查「某网站是不是被规则分错了」、或在完全受限网络下不想逐条改规则);
- **直连模式**:所有流量不走代理(测试本地网络、临时关闭代理但不想断开 VPN 丢失 DNS/统计能力)。

Stash / Clash Verge / Surge 等主流客户端均把「出站模式」作为一级功能常驻首页。sing-box 内核原生支持该机制(Clash Mode),Nest 的命令通道也已订阅相关数据流,**但当前生成的配置没有声明任何模式,导致整条链路处于休眠状态**。

## 2. 名词与机制

| 名词 | 含义 |
|---|---|
| 出站模式(Clash Mode) | sing-box `experimental.clash_api` 提供的运行时开关。模式列表由路由规则中出现的 `clash_mode` 值 + `default_mode` 汇总而来,切换即时生效、无需重启内核 |
| 规则模式(Rule) | 默认模式。不命中任何 `clash_mode` 规则,流量按现有规则链分流 |
| 全局模式(Global) | 命中 `{"clash_mode":"Global"}` 规则,全部流量交给 `GLOBAL` 选择器(成员=所有分组+所有节点,用户可在策略组页里指定具体出口) |
| 直连模式(Direct) | 命中 `{"clash_mode":"Direct"}` 规则,全部流量走 `direct` 出站 |

## 3. 目标 / 非目标

**目标**

1. 用户能在 App 内一键切换 规则 / 全局 / 直连 三种出站模式,即时生效。
2. 入口常驻页面右上角,**未展开时即可看出当前模式**(图标 + 模式名)。
3. 模式选择在 VPN 重启、App 重启后保持(内核 `cache_file` 持久化)。
4. 全局模式下用户可以指定「全局出口」用哪个节点/分组(通过策略组页的 GLOBAL 组)。

**非目标**

- 不做自定义模式(sing-box 支持任意模式名,本期只做标准三模式);
- 不做分应用模式、定时模式;
- 不改变规则模式下的现有分流行为;
- 旧配置(不含模式声明)不做运行时兼容,提示重新转换即可(见 §6)。

## 4. 交互设计

### 4.1 入口位置与形态

- **策略组页(组 tab)右上角** 与 **仪表盘页右上角** 各放一个模式入口(同一组件)。
  - 策略组页是模式语义最强的页面(全局模式要来这里选 GLOBAL 出口);
  - 仪表盘是启停主页,顺手切模式。
- 形态:`Menu` 按钮,**label 直接显示当前模式**:模式图标 + 模式短名(如「⚙︎ 规则」),而非一个含义模糊的通用图标。
- 图标约定:规则 `arrow.triangle.branch` / 全局 `globe` / 直连 `arrow.right.circle`;未知模式名回退 `circle.grid.2x2`。

### 4.2 菜单与切换

- 点开菜单列出全部可用模式(来自内核推送的 `clashModeList`),当前项打勾(`Picker` 样式)。
- 点选后:**乐观更新** label(立即显示新模式)→ 调 `setClashMode` → 内核经命令流回推 `updateClashMode` 收敛最终状态;调用失败弹 alert 并以内核状态为准。
- 切换全局模式后,策略组页会多出一个 `GLOBAL` 组(内核推送),用户在其中选出口,与 Clash/Stash 行为一致。

**立即生效(硬性要求)**:VPN 运行中切换模式必须对全部流量立刻生效——

- `setClashMode` 本身即时作用于**新连接**(内核运行时开关,无需重启);
- 但已建立的长连接(视频流、下载、长轮询)会停留在旧路径上。为此,**切换成功后主动断开全部存量连接**(`closeConnections`),迫使所有流量按新模式重建(与 Clash Verge「切换时中断连接」行为一致)。正在进行的下载/播放会闪断一次并自动重连,这是预期行为。

### 4.3 模式名显示

内核给的模式名是配置里的原始字符串(`Rule`/`Global`/`Direct`)。UI 层做大小写不敏感映射:

| 内核值 | 中文 | English |
|---|---|---|
| rule | 规则 | Rule |
| global | 全局 | Global |
| direct | 直连 | Direct |
| 其它 | 原样显示 | 原样显示 |

### 4.4 可见性与停机行为(2026-07-08 真机验收后修订)

**入口常驻**:无论 VPN 是否开启,右上角模式入口始终显示且可操作。

| 状态 | 行为 |
|---|---|
| VPN 运行中 | 显示/切换内核实际模式(列表来自内核推流),切换立即生效(断存量连接) |
| VPN 停机 | 显示/切换 **App 期望模式**(`preferredClashMode` 持久化);列表退回标准三模式;下次启动内核后自动对齐到期望模式 |
| 运行时经其它入口切换(仪表盘卡片等) | 内核回推时同步回写期望模式,停机后入口延续显示最后模式 |

> 自愈(ClashModePatcher)保证任何配置运行起来都有标准三模式,所以停机态固定展示 Rule/Global/Direct 是安全的。远程控制模式下切换远端设备,不影响本机期望模式。

### 4.4.1 组页按模式过滤(2026-07-08 真机验收后新增)

策略组页(组 tab)随当前模式变换内容,贴合 Clash 客户端习惯:

| 模式 | 组页内容 |
|---|---|
| 规则 | 全部策略组,**隐藏 GLOBAL** |
| 全局 | **只显示 GLOBAL 一个组**,自动展开,内部为**所有节点的平铺**(GLOBAL 成员=纯节点,不含分组);配置无 GLOBAL 组时回退显示全部 |
| 直连 | 空态提示「直连模式:所有流量直接连接」 |

### 4.4.2 仪表盘卡片

`Clash Mode` 卡片默认排序**第一位**;在 设置 → Dashboard Items 中可排序与隐藏(沿用现有卡片管理能力)。已保存过自定义排序的设备不受默认值影响,可用 Reset 恢复新默认。

> 注:仪表盘已有一张 `ClashModeCard` 卡片(上游遗产,可见性同为 `count > 1`,此前从未出现过)。本 feature 落地后它会自动开始显示,与右上角入口共存;用户可在「设置 → Dashboard Items」里关掉卡片。不删卡片、不改卡片。

### 4.5 各模式行为定义(验收口径)

| 行为 | 规则 | 全局 | 直连 |
|---|---|---|---|
| 命中分流规则的域名 | 按规则出站 | 走 GLOBAL 选中的出口 | 直连 |
| 未命中规则(final) | final 组 | 走 GLOBAL 选中的出口 | 直连 |
| 局域网 / 私网 IP | 直连 | **直连(不变)** | 直连 |
| DNS(国内域名) | 直连解析(真实 IP) | fakeip → 代理 | 直连解析 |
| DNS(其余域名) | fakeip → 代理 | fakeip → 代理 | **直连解析(真实 IP)** |

## 5. 依赖与前置(可行性结论摘要)

- **Nest 端零内核改动**:Libbox 已提供 `setClashMode` / `initializeClashMode` / `updateClashMode`;`CommandClient` 已订阅 `.clashMode` 并发布 `clashMode`/`clashModeList`。缺的只是右上角 UI。
- **配置端是关键路径**:mac app 转换器当前产物没有 `experimental.clash_api`、没有 `clash_mode` 路由/DNS 规则、没有 `GLOBAL` 选择器、没有 `cache_file` → 模式列表恒为 1,一切 UI 不显示。四者都要补(详见落地方案)。

## 6. 兼容与降级

- **模式能力不依赖 mac 转换器(2026-07-07 需求升级)**:Nest 用户不一定有 mac app。Nest 在内核加载配置前做**运行时自愈**(ClashModePatcher):检测配置缺少模式机制时自动补全 clash_api / clash_mode 规则 / GLOBAL 组 / cache_file。任何来源的配置(自家转换器、第三方、手写)、包括存量旧配置,**零操作**获得模式能力,无需重转。
- 自愈只发生在运行时内存中,不回写 profile;配置已含任何 `clash_mode` 规则(如新版转换器产物)则视为作者有意设计,原样放行。无法安全补全的反常配置(如 GLOBAL 名被节点占用)也原样放行——入口不显示,无报错。
- mac 转换器仍显式产出模式机制(配置级真值,可移植到其它 sing-box 客户端),与自愈互为冗余,patcher 对其自动跳过。
- `cache_file` 引入的副作用(顺带收益):**策略组的手动选点也会随之持久化**(此前 VPN 重启后所有 selector 回到 default)。需在验收中一并确认。

## 7. 验收标准

1. 新配置启动后,组页/仪表盘右上角出现模式入口,默认「规则」。
2. 切「全局」:访问 `ip.sb` 等出口 IP 与 GLOBAL 选中节点一致;国内站点也走代理;策略组页出现 GLOBAL 组且可换出口,换后出口 IP 跟随。
3. 切「直连」:出口 IP = 本机运营商 IP;国外可直达站点可访问(fakeip 域名映射回源正确);局域网设备可访问。
4. 切回「规则」:分流行为与本 feature 上线前完全一致。
5. **立即生效**:VPN 运行中切换,无需重启;切换瞬间存量连接被断开重建——正在播放的视频/进行中的下载闪断后按新模式恢复(可用持续 ping/流媒体观察验证)。
6. 模式切换后重启 VPN、杀 App 重开:模式保持。
7. VPN 停止时入口消失;重启后恢复。**删除全部配置后,任何页面都无模式入口**。
8. 中英文环境下模式名正确显示为 规则/全局/直连 与 Rule/Global/Direct。
9. 旧配置运行不出现入口、无异常。
